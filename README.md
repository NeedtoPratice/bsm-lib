# musicManage —— 音乐库维护

MPD/rmpc 曲库（默认 `~/Music`）的维护工具：把一套歌词/标签规范写进脚本，
每次运行逐步交互，改什么先给你看报告。入口只有一个脚本：`music_lib.py`。

许可：MIT（见 `LICENSE`）。

> `rules/name-overrides.txt` 与 `manual/instrumental.txt` 里各有一两条作者自己曲库的条目，
> 它们同时也是回归套件的固定用例；照着格式加你自己的即可。

```
musicManage/
├── music_lib.py          维护脚本（唯一入口）
├── rules/                规则数据（改这里，不用改代码）
│   ├── roles.txt         作者/职位写法 → 规范字段
│   ├── instruments.txt   乐器写法 → 英文乐器名
│   ├── notices.txt       来源站声明模板（正则）
│   └── name-overrides.txt 逐文件的取名覆盖（按文件名做键）
├── manual/
│   └── instrumental.txt  人工判定为纯音乐的文件清单
├── tests/
│   ├── regress.sh        回归套件（合成曲库，从不碰 ~/Music）
│   ├── audit.py          只读审计（真实曲库，只报不改）
│   └── hash.py           目录 md5 清单
├── reports/<时间戳>/     每次运行的完整报告（gitignore）
└── backups/<时间戳>/     每次运行的备份（gitignore）
```

## 一、它维护的标准

**1. `.lrc` 里只有歌词。**

```
[时间]外文歌词
[时间]罗马音        ← 若有
[时间]中文歌词
[时间]外文歌词
...
```

* 属于同一毫秒的几行必须相邻，且**每行都带同一个时间戳**；
* 没有时间戳的续行（译文、罗马音）**继承上一行的时间戳** —— 这是让多语言歌词能对齐显示的关键；
* 开头任何**不是歌词**的内容一律不保留：`[ti:]/[ar:]/[al:]/[length:]/[by:]/[hash:]/[offset:]/[total:]…`
  全部头部标签、`[awlrc:…]`/`[tlrc:…]` 这类站点元数据块、用时间轴写的作者行与标题行、
  以及 `QQ音乐享有本翻译作品的著作权` 这类来源站声明；
* 没有歌词的歌，整个文件只有一行：`[00:00.00]No lyrics`；
* **空行原样保留**（裸空行、带时间戳的空行都不动），脚本不新增也不删除空行。

**2. 音频文件名 = `歌名 - 作者.后缀`。**

* **作者取自文件名里原有的那一段**（`5th Simfoniа - At Vance` 里的 `At Vance` 是原始作者），
  写回 `TPE1`；被它替换掉的旧值（比如合辑里被统一改成 `metals` 的那种）搬进专辑作者
  `TPE2`，不丢。**歌名取自标签。**
* 这两条由**同一个函数**算，所以 `tags` 与 `rename` 先跑哪个、跑不跑，结果都一样 ——
  这一步曾经是个坑：`rename` 单独跑会读到还没修的 `metals`，把
  `5th Simfoniа - At Vance` 改成 `5th Simfoniа - metals`。
* 多人分隔符统一成 `;`（`A、B`、`A, B` → `A;B`）。实测全库只有 2 个值含 `, `，
  两个都是真的两位作者，含 ` & ` 的 0 个，所以不会误伤 `Earth, Wind & Fire`。
* 外文歌名后面跟着的 `（中文翻译）` 去掉（判据：主标题含假名 **且** 括号内是纯汉字、
  无假名无拉丁）。`ray (超かぐや姫！ Version)`、`(feat. 茶太)`、`(5人Ver.)` 都不受影响。
* 标签里的歌名如果自己就重复了 ` - 作者`（`Intro - The Ocean` + 作者 `The Ocean`），
  把结尾那截去掉，否则会变成 `Intro - The Ocean - The Ocean`。
* `TRACKNUMBER` 按标准写成不零填充的整数（`03` → `3`）。
* 歌名里出现文件名放不下的字符（`/`）时，**文件名里换成 `_`、标签保留原样**：
  `Computer Face//Pure Being` 的文件名是 `Computer Face__Pure Being`，标签里仍是 `//`。
  只在**名字**上替换，所以不丢信息，重跑还会得到同一个名字。
* 标签本身不合意、又不想动音频时，写进 `rules/name-overrides.txt`：
  `<现在的文件名> = <想要的歌名> [| <想要的作者>]`。键是**文件名**不是歌名 ——
  库里有两首歌都叫 `Odyssey`，按歌名做键会一次改中两个。生效一次后键就不匹配了，条目自动失效。
* 歌名里含 ` - ` 的文件名按**最后一个** ` - ` 切分（`Four Seasons - Spring - At Vance`），
  否则作者会被切错、名字被拼成 `Four Seasons - Spring - Spring - At Vance`。
* 没有歌词的歌，`embed` 会把 `[00:00.00]No lyrics` 这一行也写进内嵌歌词，与 `.lrc` 保持一致。

**3. `.lrc` 里有作者信息时，能写进音频标签的就写进去，写不进去才丢弃。**

## 二、每一步做什么

| 步骤 | 作用 |
|---|---|
| `ogg` | 给没有标题标签的 `.ogg` 用文件名补上 |
| `extract` | 把音频里内嵌的歌词抽成 `.lrc`（已有 `.lrc` 就不动） |
| `clean` | **把非歌词内容清干净**：能搬进标签的作者信息搬走，其余（头部标签、标题行、来源站声明、站点数据块）逐条记进报告后删除 |
| `nolyrics` | 没有歌词的歌，只写一行 `[00:00.00]No lyrics` |
| `bilingual` | 给无时间戳的续行补上上一行的时间戳，然后把同时间戳的行归拢到一起 |
| `romaji` | 把罗马音挪到外文与中文之间（目标形态是 `外文 / 罗马音 / 中文`） |
| `tags` | 让标签和文件名一致：作者、专辑作者、外文歌名的 `（中文翻译）`、标题里重复的 ` - 作者`、`TRACKNUMBER` |
| `embed` | 把清干净的 `.lrc` 写回音频的内嵌歌词（`.mp3`→`USLT`，`.flac/.ogg`→`LYRICS`，`.m4a`→`©lyr`） |
| `rename` | 音频文件名改成 `歌名 - 作者`，`.lrc` 同步改名 |

## 三、交互模型：先出报告，再问你

每一步**跑两遍**：

1. **计划**：扫描全库、把**完整报告落盘**到 `reports/<时间戳>/`，不改任何文件；
2. **询问**：

   ```
   [clean] [Enter] 看报告   [y] 执行   [s] 跳过本步   [q] 退出 >
   ```

   按 Enter 会打印报告开头（默认 60 行）并再次询问，完整清单始终在磁盘上；
3. **执行**：只有你回 `y` 才真正改文件。

所以**没有任何一行是从 `.lrc` 里悄悄消失的** —— 每一条删除都带原因进了 `clean_removed_report.txt`。

模式开关：

* 默认：交互（`stdin` 不是终端时**拒绝写入**，退出码 2）
* `--dry-run`：**什么都不写**，连报告都不写，只打印
* `--yes`：不问，直接执行（仍然写报告和备份）；留给非交互场景

> 注意：`--dry-run` 下，后面步骤的数字是按**尚未被前面步骤改过**的文件算的。
> 例如 `nolyrics` 看到的还是没清过头部的文件，所以它报的数字会比真实运行偏大。

## 四、备份

`--backup` 会把**这一轮开始前**的原件放到 `backups/<时间戳>/`，目录结构与曲库一致：

* `.lrc`：全文备份（几 KB）
* 音频：**只备份标签**（`<文件名>.tags.txt`）。整库 5.6 GB，每轮整份复制是不成立的，
  而本工具能改的只有标签。

同一轮里第一次备份生效，所以被多个步骤碰过的文件，留下的仍是"本轮之前"的样子。

## 五、为什么这么定（踩过的坑）

* **头部标签全删，包括 `[ti:]/[ar:]/[al:]/[length:]`。** 这几项 rmpc 本来可以用来索引歌词，
  删掉就只剩按文件名匹配。这是明知的取舍：歌词同时内嵌进音频标签、文件名又规范成
  `歌名 - 作者`，匹配仍有退路。
* **来源站声明只能用窄模板。** 用宽关键词（`著作权|版权|声明|提供|钢琴|吉他|演唱|轴|禁止`）实测
  35 行命中里绝大多数是真歌词：`这是一个公共服务声明`（Green Day）、`我会用吉他来演奏`、
  `总弹卡壳的钢琴…`、`温暖梦境的和声`。所以 `rules/notices.txt` 里只写"整句就是一句声明"的模板，
  拿不准的候选默认用 `#` 注掉。
* **纯音乐靠人工清单，不靠猜。** `First Light - Camel.lrc` 的正文是"人名 + 乐器"混排的制作名单
  （`Andrew Latimer` / `Guitars Pan` / `Pipes Peter`…），没有 `角色：值` 形式，也认不出人名；
  任何"猜人名"的启发式迟早会吃掉真歌词。全库 279 个有歌词的文件里只有这一个属于此类，
  所以放进 `manual/instrumental.txt` 由人拍板。
* **区头标签里的方括号曾经让纯音乐看起来"有歌词"。**
  `[ar:Black onyX [帝アキラ (cv.入野自由)…]]` 这种值里带 `[`/`]` 的头部标签，
  旧的 `is_metadata_line` 匹配不到，于是整行被当成歌词。现在头部匹配用宽松的 `.*`，这类文件归位。
* **无时间戳的头部标签不能被"续行继承"粘上时间戳。** 歌词后面出现的 `[by:someone]` 不是译文，
  给它补时间戳等于把它变成歌词。`clean` 会删掉它；在那之前一律原样留着。
* **每次运行的目录带时间戳。** 同一秒内的两次运行会撞目录并互相覆盖报告，所以重名时自动加 `-2`。

## 六、怎么验证

```bash
bash tests/regress.sh      # 合成曲库，97 项，从不碰 ~/Music
python3 tests/audit.py     # 只读审计真实曲库：改动面、敞口、不动点
python3 music_lib.py --dry-run    # 真曲库全流程预演，零写入
```

## 七、每一步都有报告

`clean` / `nolyrics` / `bilingual` / `romaji` / `tags` / `embed` / `rename` 都会写报告到
`reports/<时间戳>/`，交互运行时**先落盘再问你**。没有报告的步骤只剩 `ogg`（写 `ogg_titles_report.txt`）
和 `extract`（三个 `lrc_*_report.txt`），它们本来就有。
