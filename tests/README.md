# tests

回归、只读审计与验收工具。**从不修改你的曲库** —— `regress.sh` 只在自己的临时目录
（`tests/regress/`）里用 ffmpeg 造合成曲库。

* `regress.sh` —— 回归套件。运行 `bash regress.sh`，末行打印总数，全过时退出码 0
* `audit.py [音乐目录]` —— 只读审计真实曲库：每个步骤还会改什么、敞口在哪
* `verify.py [音乐目录]` —— 只读验收：曲库是否已符合标准，**所有计数应为 0**
* `hash.py <目录>` —— 目录内容 md5 清单，供 dry-run / 幂等性做字节级比对
* `tagval.py <文件> <键>` —— 打印一个标签值，供回归套件断言用

`regress.sh` 覆盖的行为：

* **非歌词清理**：全部头部标签（含值里带方括号的 `[ar:…[..]…]`）、来源站声明、
  用时间轴写的标题行（`作者 - 歌名` 与 `歌名 - 作者` 两种写法）、作者行；
  没有时间戳的空行删除，带时间戳的空行（`[00:12.00]`）保留
* **续行继承**：没有时间戳的译文/罗马音行拿到上一行的时间戳；空行不打断这条链
* **时间戳精度**：同一文件内统一补零到该文件已有的最高精度（值不变；已经是统一精度的
  文件不被改动）
* **占位**：没有歌词的歌只写 `[00:00.00]No lyrics`；人工声明的纯音乐文件同样处理
* **标签规范化**：作者取文件名、旧值进专辑作者、外文歌名的 `（中文翻译）` 去掉、
  标题里重复的 ` - 作者` 去掉、`TRACKNUMBER` 去零填充、多人分隔符统一 `;`
* **取名**：`歌名 - 作者`、歌名里含 ` - ` 时按最后一个分隔符切分、
  含 `/` 时在**文件名**里换成 `_`（标签保留原样）、重名冲突报告而不覆盖、
  `rules/name-overrides.txt` 逐文件覆盖并只生效一次
* **内嵌歌词**：`.mp3`→`USLT`、`.flac`→`LYRICS`，往返一致、可重复运行
* **安全性**：`--dry-run` 连报告都不写；`stdin` 不是终端时拒绝写入（退出码 2）；
  单个文件写失败不中断整轮；报告先落盘再问人；一轮结束自检音频与 `.lrc` 是否脱节
